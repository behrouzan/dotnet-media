# Image processing engine decision (28 September 2026)

The imaging slice pins **Magick.NET-Q8-AnyCPU 14.17.2**. The [NuGet package page](https://www.nuget.org/packages/Magick.NET-Q8-AnyCPU/14.17.2) lists .NET 8 support and one managed package dependency, `Magick.NET.Core` 14.17.2. The package's included `Notice.txt` identifies Magick.NET under Apache 2.0, ImageMagick under its own license, and bundled native components with separate notices. In particular, the notice identifies `libde265` and `libheif` under LGPL terms. Their distribution conditions and the full notice must be reviewed before any NuGet publication; the package's Apache label alone does not settle the bundled native licenses.

| Option | Capability and deployment | License finding |
| --- | --- | --- |
| [ImageSharp](https://github.com/SixLabors/ImageSharp) | Managed .NET, JPEG/PNG/WebP support and image processing. | Its [split license](https://github.com/SixLabors/ImageSharp/blob/main/LICENSE) grants Apache 2.0 use only under listed criteria and calls for a commercial license otherwise. A general package for unknown SaaS consumers cannot assume every consumer meets those criteria. |
| [Magick.NET](https://github.com/dlemstra/Magick.NET) | .NET binding/distribution of ImageMagick with broad format, resize and orientation features; native binaries increase package size and require runtime-specific verification. | Its repository [license](https://github.com/dlemstra/Magick.NET/blob/main/License.txt) is Apache 2.0. ImageMagick's [license](https://imagemagick.org/script/license.php) is also published by its project. Review the exact selected binary package and notices before release. |
| [NetVips](https://github.com/kleisauke/net-vips) | Efficient streaming pipeline; requires native libvips binaries and platform packaging. | Binding is [MIT](https://github.com/kleisauke/net-vips/blob/master/LICENSE), while [libvips](https://github.com/libvips/libvips/blob/master/COPYING) has separate LGPL terms. Distribution obligations need a specific review before choosing its binary packages. |

The [upstream platform matrix](https://github.com/dlemstra/Magick.NET#download-anycpu) lists Windows x86/x64/arm64, Linux x64/arm64, Linux musl x64, and macOS x64/arm64 for Q8 AnyCPU. This package was built and tested on Windows x64 in this branch. Linux and macOS deployments still need runtime smoke tests, including native asset presence. Q8 limits pixel precision; it is suitable for the initial product-photo pipeline but can lose precision from high-depth inputs.

Magick.NET is the current engineering choice because it supports the needed raster operations and has a documented package license. The implementation only accepts JPEG, PNG and WebP signatures and verifies the decoder's format. The complete native notice is distributed inside the upstream package. This record reports the inspected package contents and upstream sources, not a final legal clearance of every bundled native binary.
